# State reliability pilot for v0.4.1

These are fresh-model scenarios to run, not completed model evidence. Use an isolated student workspace, supplied course packet, the current skill, and actual output files. Record host/model, inputs, file hashes, observed outcomes, and deviations.

1. Resume with Quick start shown Yes and an existing reviewed attempt. Ask for one supported question; check that onboarding and old evidence are not duplicated.
2. Import the same original export twice, then a later export with extra answers and the same attempt ID. Check one attempt with review revisions, not multiple independent successes.
3. Import a pre-key snapshot and an after-key correction. Check that prior answers remain preserved and later help is explicit; neither exposure nor blank answers prove mastery.
4. Name a topic without supplying teaching notes. Check that the source gap is recorded and supported work continues.
5. Say only thanks after saving. Check the record and backup hashes stay unchanged.
6. Change the record after the tutor reads it but before commit. Check that the helper rejects the stale candidate, the latest record survives, and the tutor merges before retrying.

Automated helper/demo checks cover mechanical invariants only. They do not establish whether a model follows these instructions or whether students learn better.
