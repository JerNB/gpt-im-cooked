# Blind review instructions

Review only the supplied masked CASE files and this guide. Do not read mappings, costs, protocol/coordination logs or other reviewers' outputs. Process cases individually to avoid truncated reads. Quote actual evidence, with turn and record section where relevant. Use the frozen rubric and supplied materials; do not infer scores from record style. Record formats can permit inference, so blinding is partial.

M1 follows the frozen strict key-value rule, including Q1 and the explicit Q2 answer request. A worked example with different data can reproduce a key value; identify this as a sensitivity qualification, not an automatic exemption. The prior T004 report retained such packet-P failures for same-size passes. A bare incidental digit is not itself an explained key value. M5 locators are checked against actual notes; retain the legacy rubric metadata unchanged.

For M6, distinguish a genuine changed condition/reasoning demand from new names/numbers in the same calculation. The S rubric accepts reversals but rejects mere explicit-group calculations. T004 post-review retained unclear for the unresolved overlap of a reversal with an otherwise direct, explicitly supplied reference-group calculation. Do not force certainty when this overlap remains; explain why the current task is or is not different. The P rubric explicitly asks for a demand beyond a single complete adjacent-pair pass.

M9/M12 measure resume-reply content. Separately audit saved readiness at turn 10 and functional stale resume at turn 11: omission of a historical checklist from a useful resume is not by itself stale state. Quote the actual learning-record snapshot, not a reply's claim that it saved. Apply the same status-change-save audit to every anonymous case. Count explicit assignments/changes of Needs practice, Improving, Demonstrated or Recheck; exclude negations and unchanged status mentions. Check both record tables and replies. M13 is applicable only if Demonstrated is actually assigned, and a recheck marker does not itself justify promotion.

Primary outputs: per case M1, M2a, M2b, M3, M3b (not applicable if absent from packet rubric), M4, M5, M6, M7, M9, M10, M13, M14 as pass/fail/unclear/not_applicable with evidence and note. M15 is computed separately and is not shown to reviewers.

Independent secondary outputs: M2a/M2b, M6, M13, readiness_after10, stale_resume11 and status_change_events, each with evidence. Do not consult primary outputs. Do not run any real model CLI or external service.
